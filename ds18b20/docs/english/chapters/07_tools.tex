\section{Build, program and regenerate}
\subsection{PlatformIO}
Install PlatformIO, open the standalone folder and use the following commands.
The project pins ST STM32 platform version 19.6.0 and builds local vendor sources
directly. The board profile supplies MCU and probe settings; it does not mean
your custom PCB is the evaluation board.
\begin{lstlisting}[language={}]
pio run
pio run -e stm32f107vc_stlink
pio run -t upload
pio run -e stm32f107vc_stlink -t upload
\end{lstlisting}
Both environments use the same sources and linker script. The GNU startup is
local. Flash is 256 KiB and RAM is 64 KiB. First installation needs PlatformIO
tool downloads; thereafter the project does not depend on sibling folders.

\subsection{Keil}
Open MDK-ARM/DS18B20.uvprojx. Install the STM32F1 device pack and Arm Compiler 6.
Select the available SWD probe under Options for Target / Debug and Utilities.
Set the STM32F10x 256 KiB Flash programming algorithm, Build, then Download.
Watch the ROM, temperature and status arrays and the completed cycle counter.
Project XML and source membership were checked; an actual Keil build was not
performed because the compiler installation was not located in this environment.

\subsection{CubeMX regeneration without losing the library}
Open DS18B20.ioc, preserve the 8 MHz clock assumptions, PB10 open-drain configuration
and Keep User Code. Libraries and Application are outside the generator's Core.
The include and App calls are inside USER CODE blocks. CubeMX may rewrite the
Keil project, so the configured post-generation script restores user source
groups and include directories. If a relative script path is not resolved by
your CubeMX version, select tools/post\_generate.cmd explicitly in User Actions.
After every Generate, run:
\begin{lstlisting}[language={}]
python tools/sync_keil.py
python tools/check_project.py
pio run
\end{lstlisting}
The synchronization is idempotent, keeps the full Flash size, adds Arm startup,
and discovers Application, Libraries and local HAL C sources. PlatformIO uses
source wildcards; add the include directory of every new library manually.
For a new peripheral, inspect HAL configuration, CubeMX interrupt handlers and
MSP initialization too. Review the diff and build Keil. Real CubeMX regeneration
has not been executed here; the structural checks document expected invariants.

\subsection{Use the next-project template}
Copy the entire raw template folder to a new project directory. It contains
only the clock, SWD, startup, vendor support and empty App hooks. Rename the
project using CubeMX when appropriate, rerun synchronization, add the next
library and its pin settings, and create a local status file and bilingual
reports. Keep each project's dependencies inside that folder.

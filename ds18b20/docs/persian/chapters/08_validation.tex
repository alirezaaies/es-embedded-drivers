\section{اعتبارسنجی و پذیرش روی برد}
\subsection{شواهد خودکار}
ساخت PlatformIO نمونه و قالب خام موفق شده است. بررسی ساختاری مسیرهای محلی،
عضویت فایل‌ها و شروع اسمبلی، بلوک‌های کاربر، تنظیم پایه و اندازهٔ فلش را
کنترل می‌کند. آزمون‌ها C واقعی را کامپایل و روی شبیه‌ساز هسته اجرا می‌کنند.
\begin{LTR}
\begin{lstlisting}[language={}]
python -m pip install unicorn
python tests/run_tests.py
python tools/check_project.py
\end{lstlisting}
\end{LTR}
یک مجموعه پاسخ پروتکل را شبیه‌سازی و ترتیب، تعویض، ابهام، کشف ناقص، سرریز،
خطای CRC، قطع سنسور، timeout، علامت دما، بازه و سرریز tick را بررسی می‌کند.
مجموعهٔ دیگر کد واقعی باس را با نمونه‌های خط اجرا می‌کند و خطای حضور، بردار
CRC، جست‌وجوی ROM و تأخیرهای حساس درخواست‌شده را می‌سنجد. این آزمون‌ها اثبات
صحت الکترونیک و زمان‌بندی آنالوگ برد نیستند.

\subsection{مراحل آزمون برد}
با پروگرامر انتخاب‌شده بسازید و پروگرام کنید. یک سنسور با تغذیهٔ خارجی وصل
کنید و پس از چرخهٔ کامل آدرس، وضعیت و دمای محیط را ثبت کنید. سنسورها را
یکی‌یکی اضافه و خانه‌های جدید را بررسی کنید. آدرس‌های معلوم را تنظیم و ترتیب
پس از ریست را کنترل کنید. یک سنسور را قطع کنید؛ وضعیت باید خطا و دما نامعتبر
شود. سنسور جدید باید پس از کشف در همان خانه قرار گیرد. دو تعویض هم‌زمان باید
تا انتخاب دستی نگاشت قبلی را حفظ کنند. نبود مقاومت و خط پایین را با روش امن
بررسی کنید. موج را زیر بار وقفه و دما را در چند نقطه با مرجع مستقل مقایسه کنید.
نتایج فیزیکی هنوز ثبت نشده‌اند.

\subsection{نگهداری مستندات}
وضعیت پروژه را پس از هر مرحله به‌روز کنید. بررسی سورس، ساخت کامپایلر، تولید
واقعی و اندازه‌گیری برد را جداگانه ثبت کنید. دیتاشیت دانلودشده را داخل پروژه
نگه ندارید؛ پیوند رسمی و فایل منابع کافی است. PDF نهایی گزارش در هر دو زبان
همراه منبع قابل‌ویرایش در Git نگهداری و در GitHub منتشر می‌شود. پس از تغییر
گزارش، هر دو PDF را دوباره بسازید و بررسی کنید. فونت دانلودشده، تصاویر بررسی
و فایل‌های موقت ساخت محلی‌اند و وارد Git نمی‌شوند.

\section{افزودن درایور مستقل بعدی}
\subsection{شروع از کپی قالب پایه}
قالب خام را کامل در پوشه‌ای به نام قطعه کپی کنید. IOC، target کیل و خروجی را نام‌گذاری و سخت‌افزار را در CubeMX تنظیم کنید. پروژهٔ کپی‌شده باید فایل‌های vendor و ساخت خود را داشته باشد. پس از کپی، مسیر هدر یا سورس به قالب یا پروژهٔ مجاور اشاره نکند.

ابتدا دیتاشیت رسمی را بخوانید و شماره، نسخه و URL رسمی را در README ثبت کنید. PDF دانلودشده محلی بماند. کوچک‌ترین عملیات کاربردی، واحد خروجی، رفتار timeout و سیاست خطا را پیش از API بزرگ‌تر تعریف کنید.

\subsection{ترتیب توسعهٔ قابل تکرار}
\begin{enumerate}
\item پایه، کلاک و فرض تغذیه را در IOC محلی تنظیم کنید.
\item هدر و پیاده‌سازی کوچک قابل‌حمل بسازید. HAL و رجیستر فقط در آداپتر باشند.
\item نمونهٔ کامل اجرایی برد با مقدار و خطای قابل مشاهده اضافه کنید.
\item اتصال برنامه در USER CODE باشد؛ در کپی موقت Generate و حفظ کد بررسی شود.
\item کیل sync شود؛ ساختار، ساخت کیل و PlatformIO و تست معنادار پروتکل و خطا بررسی شوند.
\item README مستقل، ابتدا انگلیسی و سپس فارسی نوشته و وضعیت با شواهد واقعی به‌روز شود.
\item یک فصل به هر نسخهٔ مرکزی گزارش و یک سطر به فهرست مخزن افزوده و هر دو PDF ساخته شود.
\item پذیرش واقعی برد انجام و اندازه‌گیری‌ها بدون حذف شواهد نرم‌افزار اضافه شوند.
\end{enumerate}

\subsection{افزودن فصل به همین گزارش}
در دو پوشهٔ chapters فایل شماره‌دار متناظر بسازید و دستور input آن‌ها را پیش از فصل توسعه به هر دو main اضافه کنید. بخش تماس آخر بماند. فصل قطعه همان ترتیب فصل دما را دارد: هدف، اتصال، اولین اجرا، پروتکل، API، دلیل پیاده‌سازی، آداپتر، Generate، خطا، پذیرش و استفادهٔ دوباره. منبع رسمی به هر دو فایل bib اضافه و در محل استفاده cite شود.

موتور هر دو نسخه XeLaTeX، زبان فارسی XePersian و منابع IEEEtran و BibTeX هستند. تم مشترک، فاصلهٔ متن ۱٫۵، آیکون کوچک لینک و شش مقصد نویسنده در config تنظیم می‌شوند. اصطلاح لاتین فارسی با lr یا محیط LTR و در خط مستقل سورس قرار گیرد تا ویرایش آسان بماند.

از ریشهٔ مخزن اجرا کنید:
\begin{LTR}
\begin{lstlisting}[language={},numbers=none]
python docs/tools/build_reports.py
python docs/tools/verify_reports.py
\end{lstlisting}
\end{LTR}
ابزار ساخت یک بار XeLaTeX، سپس BibTeX و دو بار دیگر XeLaTeX را اجرا می‌کند. verifier، نام نویسنده، شش مقصد در پاورقی هر صفحه و محدودهٔ صفحه را بررسی و صفحات را برای مشاهده render می‌کند. contact sheet و صفحه‌های کامل را هم ببینید؛ تست خودکار لینک به‌تنهایی کیفیت صفحه‌آرایی را ثابت نمی‌کند. فونت و تصویر بررسی ignored هستند؛ PDF نهایی tracked است.
